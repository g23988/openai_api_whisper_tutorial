Chapter 3

API 是什麼

這章不寫程式。我們暫停一下，把「API 到底是什麼」這個觀念真的講清楚。後面所有章節都會用到這個觀念，但如果你心裡沒有清晰的模型，再多範例也只是抄。

很多入門教材對 API 的解釋是「Application Programming Interface 應用程式介面」——這個翻譯沒錯，但等於沒講。我們從一個更具體的角度切入。

ChatGPT 跟 OpenAI API 差在哪

你大概用過 ChatGPT。打開瀏覽器、登入、輸入問題、看模型回答。這是 OpenAI 提供的產品——一個給人類用的網頁介面，背後有對話歷史、付費機制、共享連結、語音輸入這些功能，全部包好給你。

但如果你想做的事是：

  • 把每天的會議錄音自動轉成逐字稿並寄到 email
  • 在公司內部網站上加一個「自動回覆客戶問題」的按鈕
  • 寫一個腳本把 5000 篇文章一次整理成摘要

ChatGPT 做不到——它沒有「給程式呼叫」的入口。你不可能寫程式自動去 ChatGPT 網頁打字。

這就是 API（Application Programming Interface）的角色：OpenAI 把同一個模型（甚至更強的模型）開放成「給程式呼叫的入口」。你的 Python 程式可以送一個請求過去，OpenAI 的伺服器跑模型、回給你結果。沒有網頁、沒有登入畫面、沒有對話歷史——純粹是一進一出的計算服務。

可以這樣理解：

ChatGPTOpenAI API
對象人類程式
介面網頁、AppHTTP request
計費每月訂閱（或免費）用多少付多少（per token）
對話歷史自動保存自己處理
適合日常使用、互動探索自動化、批量處理、整合進工具

兩個都很好，但用途不同。本課要教的是後者。

一個更貼切的比喻

如果你經營一間餐廳，你會有：

  • 內用大廳：給客人坐下來慢慢吃，有桌椅、餐具、服務生、菜單。
  • 後門：給外送平台 Uber Eats 來取餐——沒有桌椅，車一停、餐一交、車就走。

兩邊的廚房是同一個。但前面那個是給人類用的「產品」，後面那個是給「其他系統」用的接口。

ChatGPT 是內用大廳。OpenAI API 是後門。同一批廚師、同一份食材，但服務的對象與形式完全不同。

Tip 這個「同一套能力，兩種接口」的模式不只在 OpenAI 出現。Google 有 Google Maps 網站，也有 Google Maps API；Stripe 有付款網頁，也有 Stripe API；YouTube 有網站，也有 YouTube API。所有規模到一定程度的軟體公司，幾乎都會同時提供「給人用」與「給程式用」兩種介面。這幾乎是現代軟體的標準商業模式，被 a16z 等矽谷投資人稱為「API 經濟」。

一通 API call 在幹嘛

具體一點。當你在 Python 寫：

client.responses.create(
    model="gpt-4o",
    input="用一句話解釋什麼是 API。",
)

電腦在做的事其實是：

  1. 把你的問題打包成一份「文件」（叫做 JSON，下一章詳細講）
  2. 透過網路送到 OpenAI 的伺服器（網址是 api.openai.com）
  3. 順便附上你的 API key 證明「我是付過錢的客戶」
  4. 等對方收到、跑模型、回應
  5. 把對方回的「文件」拆開，把模型講的話拿出來給你

整個流程跟你打電話訂披薩很像：

  • 撥號（連到伺服器）
  • 報名字（API key）
  • 點餐（input + model）
  • 等對方確認（網路傳輸）
  • 收到回覆（response）

差別只是這通電話是程式打的，對話內容是 JSON 格式，整個流程通常在 2 秒內完成。

API key 是什麼

API key 是一串看起來像 sk-... 的字串，是 OpenAI 給你的「身份證」。每次你呼叫 API，這串字串會跟著請求一起送過去，OpenAI 才知道：

  • 這個請求是誰打來的
  • 用量要記在誰的帳上
  • 有沒有超過額度

換句話說，有你的 API key 的人，等於可以用你的帳號花錢。所以保護 API key 是這套課貫穿始終的主題，後面 Chapter 5 跟 Chapter 16 會重點講。

Warning 三個絕對不要做的事：(1) 把 API key 寫死在程式碼裡並 push 到 GitHub；(2) 把 API key 貼在前端 JavaScript（瀏覽器任何人都看得到）；(3) 把含有 API key 的截圖傳給任何人。GitHub 上有偵測 bot，洩漏的 key 通常幾分鐘內就會被自動撤銷——但也可能在被撤銷前就被別人拿去打爆額度。本課所有範例都用環境變數 OPENAI_API_KEY 來傳遞 key，從不寫死在程式碼。

Token、模型、費用的基本直覺

每次呼叫 API 都要花錢，金額取決於三件事：

  • 用哪個模型：gpt-4o 比 gpt-4o-mini 貴，o1 比兩者都貴
  • 送進去多少 token（你的問題、檔案內容）
  • 模型輸出多少 token（回答長度）

Token 不等於字。粗略對應：1 token ≈ 0.75 個英文單字 ≈ 0.5 到 1 個中文字。本課 Chapter 16 會講怎麼用 tiktoken 工具精確計算。

現在你只需要建立一個直覺：

  • 問一句話、回一句話：通常不到 0.001 美金
  • 整理一份 10 分鐘會議逐字稿（語音轉文字 + 摘要）：通常幾美分到一兩毛
  • 批量處理一千份文件：就要認真算了
Note 這個量級對個人或小型工具來說很便宜（一天搞個小專案花 1-2 美金就玩得很開心），但對「跑在生產環境、每天幾萬個請求」的服務來說，成本是真實的。本課後面我們會做的工具屬於前者，但 Chapter 16 還是會教怎麼估算成本，因為這個技能你遲早用得到。

為什麼不用 ChatGPT 就好

你可能會想：「我每天用 ChatGPT 也能整理會議紀錄，為什麼還要學 API？」

務實的答案有四個：

1. 自動化。 ChatGPT 你得手動貼內容、手動複製結果。API 可以接上「定時抓 email」「自動掃資料夾」「直接寫進資料庫」，變成不需要你介入的流程。

2. 整合進你自己的工具。 ChatGPT 是 OpenAI 的網頁，你不能在裡面加你公司的按鈕、不能整合公司的客戶資料。但 API 可以變成你自己 app 的一部分。

3. 結構化處理。 API 可以強制模型輸出固定格式 JSON（本課 Chapter 13 會教），讓結果直接給其他程式使用。ChatGPT 雖然也能做，但需要每次手動複製貼上。

4. 細部控制。 API 給你很多 ChatGPT 沒有的旋鈕：溫度、輸出長度、結構化 schema、streaming、tool calling……這些都是「做工具」時的必要工具。

反過來說，如果你只是想自己問問題、隨意聊聊、探索想法，繼續用 ChatGPT 就好。API 是給「想做工具」的人準備的——這也是本課的所有讀者應該是的角色。

小結

這章我們把幾個關鍵觀念講清楚了：

  1. ChatGPT 是給人用的產品，API 是給程式呼叫的接口——共用同一批模型，但形式完全不同
  2. API call 就是「程式之間的電話」——透過網路送請求、拿回應
  3. API key 是你的身份證，洩漏等於有人可以花你的錢
  4. API 計費按 token——粗略對應字數，本課後面會教精確估算
  5. API 適合自動化、整合、結構化處理；ChatGPT 適合互動、探索

下一章 Chapter 4 會把「API call 的內部結構」拆開來看——什麼是 HTTP、什麼是 JSON、status code 是在說什麼。理解了那層，OpenAI SDK 對你來說就不是黑箱了。

練習

  1. 想三個你日常生活或工作中「重複做、很煩、希望自動化」的場景。哪些可以用 OpenAI API 加上一點 Python 處理？
  2. 看 OpenAI 的定價頁（自己 Google），找出 gpt-4o、gpt-4o-mini、whisper-1 三個的每百萬 token 或每分鐘音訊的價格。
  3. 想一個你身邊的人會用的小工具：給定一段中文，產生英文摘要。如果這個工具一天會被用 100 次，每次平均 500 字輸入 + 200 字輸出，用 gpt-4o-mini 大概一個月要多少錢？（粗估即可，下一章我們會用真實數字算）
